# Cognitive Load Management Rules

> 来源: fix-evolution-flywheel 实施复盘 — 问题 #10~#12
> 最后更新: 2026-05-11

## CLM-1: 决策记录

**规则**: 面对结构性问题时，**必须**将结论写下来。

**禁止行为**:
- 依赖记忆来回查看同一段代码
- 在脑中反复推理而不记录
- 读取 5+ 次后才开始行动

**正确做法**:
```markdown
## 决策: continue-loop 在 DRY_RUN 块内还是外?

事实:
- DRY_RUN if 开始: L1021
- Phase 7 else 块结束: L1217
- continue-loop while: L1221
- phase_end "7": L1220

结论: continue-loop 在 DRY_RUN if/else 块**外部**（Phase 7 else 块结束后才到达）
```

*→ 防止: 问题 #10（10+ 次重复读取）、#11（300 行循环思考）*

## CLM-2: 单问题时间上限

**规则**: 在同一问题上卡住超过 **5 分钟**时，**必须**执行以下之一:

| 选项 | 适用场景 |
|------|----------|
| (a) 向用户提问 | 架构决策、需求不清 |
| (b) 选择一个方案并记录假设继续前进 | 技术实现路线不确定 |
| (c) 放弃该子任务 | 问题超出当前能力范围 |

**正确做法**:
```
## 问题: Phase 7 DRY_RUN 块的完整结构是什么?

5分钟后仍未确定 → 选择方案 (b):
假设: continue-loop 在 Phase 7 else 块外部
验证方式: 运行 dry-run，观察 continue-loop 是否执行
```

*→ 防止: 问题 #11（300 行循环思考）*

## CLM-3: 代码阅读次数上限

**规则**: 同一段代码（±20 行范围）最多读取 **3 次**。

| 次数 | 目的 |
|------|------|
| 第 1 次 | 获取关键行号（函数/if/while 的位置） |
| 第 2 次 | 确认边界（控制流配对关系） |
| 第 3 次 | 画出结构图 |

**第 3 次仍未理解时，必须**:
1. 画出流程图
2. 列出所有不确定的点
3. 向用户求助或选择方案继续

**禁止**: 第 4 次读取同一段代码而不记录任何结论

*→ 防止: 问题 #10（10+ 次重复读取）*

---

## CLM-4: 输出解释而非自言自语

**规则**: 分析代码时，将结论写成简短的 **"事实 → 判断 → 行动"** 格式。

**禁止格式**:
```
让我再看看这里...嗯这个结构...等等我觉得可能是...不对让我再确认一下...
实际上这个 if 应该在...让我再读取一次...
```

**正确格式**:
```
## 分析结论

事实:
- L1021: if [ "$DRY_RUN" = true ]; then
- L1025: else
- L1220: phase_end "7"

判断: Phase 7 的 DRY_RUN if/else 块结束于 L1220。
       continue-loop (L1221) 在此之后。

行动: 在 continue-loop 前添加 DRY_RUN 检查。
```

**目的**: 减少认知漂移，保持思路清晰

*→ 防止: 认知漂移、浪费时间*

## Scenario: 不确定某段代码是否在条件块内部

**情境**: 不确定 `continue-loop` 是否在 DRY_RUN 的 if/else 内部

**执行步骤**:

**第 1 次读取**:
- 目标: 获取 if 和 while 的行号
- 记录: `DRY_RUN if: L1021`, `while: L1221`

**第 2 次读取**:
- 目标: 确认 phase_end "7" 的位置
- 记录: `phase_end "7": L1220`

**第 3 次读取**:
- 目标: 画出完整结构图
- 输出:
```
L1021: if [ "$DRY_RUN" = true ]; then
L1025: else
...
L1217: fi  ← Phase 7 if/else 结束
L1220: phase_end "7"
L1221: CONTINUE_LOOP_COUNT=0  ← 在 Phase 7 if/else 外部
L1226: while true; do
...
L1310: done
```

**结论**: continue-loop 在 DRY_RUN if/else 块**外部**。需要在其前添加 DRY_RUN 检查。

**如果仍不确定**:
- grep 所有 `fi` 出现位置并编号
- 确认每个 fi 对应哪个 if
- 写下结论，**禁止继续读取**

## Scenario: dry-run 输出误读

**情境**: 看到 dry-run 输出部分内容后不确定脚本是否正常完成

**执行步骤**:

1. **先确认命令是否仍在运行**:
   ```bash
   # 检查命令 ID 是否存在
   # 如果存在，等待完成
   ```

2. **确认输出截断**:
   ```
   使用: 2>&1 | tail -N
   而不是只看开头或中间部分
   ```

3. **确认关键指标**:
   - [ ] Phase 8 是否到达（搜索 "Phase 8"）
   - [ ] 是否有 syntax error（搜索 "error"）
   - [ ] 是否有 unbound variable（搜索 "unbound"）
   - [ ] 时间报告是否输出（搜索 "TOTAL"）

4. **记录结论**:
   ```
   ## dry-run 输出分析
   
   观察到: "Phase 7 elapsed: 0s" 后无输出
   检查: grep -c "Phase 8" = 0
   结论: Phase 8 未到达，脚本可能在 Phase 7 后退出
   原因: 疑似语法错误（待验证）
   ```

*→ 防止: 问题 #12（dry-run 输出多次误读）*

## 认知负载管理快速检查表

**开始任何代码修改前**:
- [ ] 我知道要修改的代码在文件的哪个范围吗？
- [ ] 我理解这段代码的控制流结构吗？
- [ ] 我计划如何验证修改是否正确？

**修改过程中**:
- [ ] 我在重复读取同一段代码吗？（如果是 → 记录结论）
- [ ] 我在同一问题上卡了超过 5 分钟吗？（如果是 → 选择方案继续）
- [ ] 我的输出是"事实→判断→行动"格式吗？

**修改完成后**:
- [ ] `bash -n` 通过了吗？
- [ ] 我记录了所做的修改吗？
